## 一、前后不一

### 1. 🔴 `subtitle.js` 仍用 localStorage 歌词缓存，`lyric.js` 已搬后端

**位置**：`go/web/assets/subtitle.js:103-134` vs `go/web/assets/lyric.js`（歌词行缓存已搬后端 lyriccache）

- `lyric.js` 注释：**"歌词行缓存已搬后端（lyriccache，与音频同逻辑；/api/v1/music/lyric 透明缓存），前端不再 localStorage 缓存歌词行（旧 hc:lyc:cache 数据弃用）"**。
- `subtitle.js:103-134` **仍完整保留 `hc:lyc:cache` localStorage 缓存**：读时 `JSON.parse` + 更新 `row.at` + 全量 `setItem`；写时再 `JSON.parse` + `setItem` + LRU 淘汰。

同一份歌词数据，**两条缓存策略并存**：字幕条走本地 localStorage（无完整性校验、会过期），歌词页走后端 lyriccache（统一、有 TTL）。且 `subtitle.js` 缓存命中**优先于**后端 `/music/lyric`（L111-116 `if (cached ...) return`），导致字幕条可能显示旧词、歌词页显示新词——**同一首歌两处显示不一致**。

**修法**：删 `subtitle.js` 的 `hc:lyc:cache` 读/写分支，统一走后端 `/music/lyric?bvid=`（与 lyric.js 一致），本地缓存只留 `hc:subpos`/`hc:subsize` 这类 UI 偏好。

### 2. 🟢 `subtitle.js` 注释与 `lyric.js` 的"缓存已搬后端"表述矛盾

同上，`subtitle.js:103` 注释仍写"与歌词面板共用 hc:lyc:cache"，而 lyric.js 已明确弃用该键。属注释/实现漂移，随 #1 一起修。

## 二、影响性能

### 1. 🟡 `subtitle.js` 的 `showBar()` 每 state 事件强制 reflow

**位置**：`subtitle.js:76` + `:178`

```js
function showBar() { bar.hidden = false; bar.style.display = ''; place(); ... }
...
hcBus.on('state', (d) => { ... if (enabled && !isAndroid) showBar(); });  // state 事件 ~250ms 一次
```

`state` 事件（`state.js:applyProgress` 节流 250ms 发出）每次触发都调 `showBar()`，而 `showBar()` 里 `place()` 读 `bar.offsetWidth`（**强制 reflow**）。播放时每 250ms 一次布局重算，即使字幕条已经显示、位置没变。

**修法**：`showBar` 开头加 `if (!bar.hidden) return;`（已显示则不动）。

### 2. 🟡 `lyric.js` `highlightLine` 每次全量遍历 DOM

**位置**：`lyric.js:131`

```js
linesEl.querySelectorAll('.ly-line').forEach((d, i) => {
  d.classList.toggle('ly-active', ...); d.classList.toggle('text-white', ...);
  d.classList.toggle('font-semibold', ...); d.classList.toggle('text-gray-500', ...);
  d.classList.toggle('scale-100', ...); d.classList.toggle('scale-110', ...);
});
```

`lyric-line` 事件（SSE，约 250ms 一次）每次都 `querySelectorAll` 遍历**所有行** + 每行 6 次 `classList.toggle`。长歌/翻译几百行 → 每 250ms 遍历几百 DOM 节点 × 6。且 `findIndex`（L127）也全量扫行数组。

**修法**：只切换 `lastIdx` 与 `idx` 两个节点（记住上一个 active 节点，`prev.classList.remove(...); cur.classList.add(...)`），不全量遍历。

### 3. 🟢 `queue.js` `render()` 全量重建 + 逐行绑定

**位置**：`queue.js:render`（L96-160）

每次 `hc:queue` 事件全量 `innerHTML` 重建整个队列 + `querySelectorAll('.hx-play'/.q-del/.q-title/.q-next/.q-fav').forEach` 逐个 `addEventListener`。队列几十首 → 每次几十个监听器重建。队列变化低频，属**设计取舍**（"能重绘就别同步"），但行内播放/删除/标题的 click 监听完全可以用**事件委托**（一个容器级 listener），省掉 N 个绑定。

**修法**：容器级 `view.addEventListener('click', ...)` 委托，按 `e.target.closest('.hx-play')` 分发；删掉 `forEach` 绑定。

## 三、低能

### 1. 🟢 `lyric.js` `titleToSong` 内联正则每次编译

**位置**：`lyric.js:177-180`

```js
function titleToSong(t) {
  const clean = (t || '').replace(/[\[【][^\]】]*[\]】]/g, '');  // ← 每次调用编译正则
```

与第三批 `web.go:ShortTitle` 同模式。`load` 里被调 2 次、`renderCandBar` 里 1 次，每次编译。

**修法**：提为包级 `const bracketRe = /[\[【][^\]】]*[\]】]/g`。

### 2. 🟢 `contextmenu.js` 降级 `toggleFav` 每次拉全量收藏列表

**位置**：`contextmenu.js:91-92`

```js
// 降级（无 hcFav）：原逻辑
fetch('/api/v1/fav/list')  // ← 每次右键"收藏"都拉全量收藏列表判断是否已收藏
```

有 `hcFav` 时走统一入口（好），但 `hcFav` 未加载时降级分支每次右键收藏都拉全量列表。应缓存已收藏集合或复用 hcFav 的加载。

**修法**：降级分支也读 `hcFav` 已加载的集合；或删降级（hcFav 是常驻）。

### 3. 🟢 `subtitle.js` 缓存读全量 JSON 重写

**位置**：`subtitle.js:106-108`

```js
const m = JSON.parse(localStorage.getItem('hc:lyc:cache') || '{}');
const row = m[s.bvid];
if (row) { row.at = Date.now(); m[s.bvid] = row; localStorage.setItem('hc:lyc:cache', JSON.stringify(m)); }
```

每次切歌读缓存都 `JSON.parse` 整个对象 + `JSON.stringify` 整个对象（更新 `at`）。50 首 LRU 全量序列化。随 #1 删缓存分支一并消除。
