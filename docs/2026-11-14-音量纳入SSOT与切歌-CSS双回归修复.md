# 音箱音量/静音纳入后端 SSOT + 切歌/CSS 双回归修复

> 一次真机使用踩出三个 bug：主动切歌面板不切换、搜索页刷新 CSS 全丢、音箱音量/静音控制不可靠。
> 三者都已修，本文记录根因与修法（含一个"完整修"的架构决策）。

## Bug 1：音箱放歌时搜歌放，面板信息不切换

**现象**：投歌模式，音箱正播 A，用户搜歌点 B → 音箱切到 B 了，但前端面板（歌名/封面）还停 A。
F5 刷新后歌曲信息又正常了（说明后端状态一直对，纯前端渲染层）。

**根因**：`PlaybackState.Play()` **漏设 `manualSwitchAt` 防污染窗**（`Next/Prev` 都设了）。
时序：`Play(B)` 切核心+广播 B → 音箱还没拉到 B 流、`Position()` 仍报 A → 1s 内
`progressLoop→projectProgress` 看到 `info.BVID(A) != cur.BVID(B)`，因 `manualSwitchAt` 是零值
保护窗不生效 → 走"音箱领先→核心跟随设备"分支 → **把核心 BVID/Title 刷回 A** → 面板回退。

**修法**：`Play()` 也设 `manualSwitchAt`。但无脑设会误伤蓝牙跟随（`TestProgressLoopProjectsSpeakerSong`
红：音箱换到完全不同歌应被跟随）。故精修——加 `prevBVID` 字段，守卫**只挡"音箱还报刚切走那首"
（滞后）**，放行"音箱换到别的歌"（蓝牙领先）：
```go
if time.Since(p.manualSwitchAt) < 3*time.Second && info.BVID == p.prevBVID {
    return // 只挡滞后，放行蓝牙领先
}
```
`Play/Next/Prev` 三处都设 `manualSwitchAt` + `prevBVID`。

**验证**：新增 `TestPlayGuardAgainstStaleSpeakerProgress`（注释修复→红，恢复→绿）；
蓝牙跟随 `TestProgressLoopProjectsSpeakerSong` 仍绿。

## Bug 2：搜索页 F5 → CSS 全丢

**现象**：在 `/hx/search?kw=X&hc=1` 刷新 → 页面结构在但样式全无。

**排查**：Playwright 实证——刷新后 `styleSheets=[]`、`window.tailwind=false`、页面是
`<html><head></head><body><div class="space-y-6">` **裸片段**（无 shell/head/CSS）。

**根因**：`hx/search.go` 的 `isHX` 多认了 `?hc=1`：
```go
isHX := r.Header.Get("HX-Request") != "" || r.URL.Query().Get("hc") == "1"
```
`hc=1` 本是给 wails 壳（不透传 HX-Request 头）补的标记，但 htmx `hx-push-url` 把它写进地址栏
→ 浏览器**刷新带 `hc=1`** → server 误判成 htmx 请求 → 返回**裸片段**（无 shell/CSS）。

**修法**：`isHX` 只认 `HX-Request` 头（htmx 自动带；刷新/直达是裸请求不带）：
```go
isHX := r.Header.Get("HX-Request") != ""
```
**验证**：搜索页 F5 后有 shell + 3 样式表 + tailwind + body 渐变背景，CSS 正常。

## Bug 3（完整修）：音箱音量/静音控制不可靠

**现象**：音箱模式拖滑块/点静音那一刻有效，但换歌后音量/静音丢失、多端不同步、取消静音滑块停 0。

**诊断**（通读链路）发现 4 个问题：
1. `State.Volume` json tag 带 `omitempty` → **volume=0（静音）被吞掉，SSE 广播不出去**
2. `PlaybackState` 无 `SetVolume`，音量没入 SSOT（`Output.SetVolume` 死路无人调）
3. 换歌/音箱重启后音量不重应用 → 静音丢失突然出声
4. 前端 `volMuted` 全局变量被 web/speaker 共用 → speaker 静音污染 web

**完整修决策**：音量纳入**后端 SSOT（仅 speaker 模式；web 音量前端本地管不进 SSOT）**。

后端：
- `State.Volume int`（**无 omitempty**，volume=0 静音必须广播）
- `PlaybackState.SetVolume(v)`：走 `Output.SetVolume` 真调音箱 + 存 SSOT + 广播
- `wantVolume` + `Play` 成功后重应用 → 换歌/重启不丢音量/静音
- `SpeakerOutput.Volume()` 回读真实音量 + `SwitchSpeaker` 时对齐（接口断言避免 playback→speaker 循环依赖）
- command 加 `set_volume` case

前端：
- `applyState` 仅 speaker 应用 volume（直接赋 `el.vol.value` 不触发 input → 不回环）
- `setVol/mute` 走 `set_volume` command
- 静音 bug：取消静音补滑块同步 + `def=0` 兜底
- `volMuted` 按音源隔离 + 切回 web 恢复本地音量态（`lastSource` 检测 source 切换）

**验证**：
- speaker 模式 set 60/0/75 滑块全跟（静音 0 修复生效）
- web 模式本地音量独立，speaker 静音再切回 web 保持原值不被压 0
- 新增 `TestVolumeSSOTAndReapply`（SetVolume 入 SSOT + 换歌重应用静音/音量）

## 经验

- **主动切歌防污染窗**必须覆盖所有切歌入口（Play/Next/Prev），漏一个就面板错乱；且守卫要精
  （只挡滞后、放行领先），否则误伤蓝牙跟随。
- **`hc=1` 这类"请求标记"别进 URL**——会被 htmx push-url 固化，浏览器刷新就变裸请求被误判。
  判定 htmx 请求只认 `HX-Request` 头。
- **`omitempty` 会吞合法零值**：volume=0（静音）是合法状态，加 omitempty 就广播不出去。
- **音量这类"设备设置项"要入 SSOT 才可靠**：靠前端"用户主动操作才下发"会在换歌/重启/多端场景
  丢失；且要有"播放入口重应用"，否则静音守不住。
- **跨音源共享的可变状态（volMuted）是坑**：web/speaker 独立音域，切换要各自恢复，别共用一个变量。
