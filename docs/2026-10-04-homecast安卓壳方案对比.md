# homecast 安卓壳方案对比：Wails v3 vs 手搓 WebView 壳

## 背景

homecast（个人 B 站音乐播放器，给爸妈用）的安卓版一直是"纯 Go 服务端二进制 + 极简 WebView 壳"（零 Gradle 手搓 APK），因为 Wails v3 的安卓支持以前只是 experimental，等它"转正"。2026-10-01 v3.0.0-beta.27 发布后，实测发现**它已经能完整干活，且部署体验比手搓壳顺得多**——这篇记录对比实测数据和结论。

两个版本（waydroid x86_64 上同场对比）：

| 版本 | 包名 | 架构 |
|---|---|---|
| **wails3 壳** | com.homecast.app | Go 编 `libwails.so`（JNI）进 APK，单进程，WebView 加载 `wails.localhost` → homecast 全部路由（`server.New()` 挂到 `AssetOptions.Handler`） |
| **手搓壳** | com.homecast.legacy | 独立 `hc-server` 进程（监听 28976）+ WebView 壳，自管生命周期 |

## 核心机制

**wails3 怎么内嵌 homecast**（关键就两招）：

```go
// 1. homecast 整个 http.Handler 挂进 asset server，WebView 的 wails.localhost 请求全走它
Assets: application.AssetOptions{ Handler: server.New() }

// 2. 安卓 app 进程无 HOME：指向私有目录，homecast 数据 ~/.config/homecast 原样落盘
// ensurehome_android.go（//go:build android）
if os.Getenv("HOME") == "" {
    os.Setenv("HOME", application.Android.StoragePath()) // getFilesDir()
}
```

WebView 只能加载 `wails.localhost`（安卓的 `setURL` 是空实现），但这恰好够用：homecast 的模板渲染、`/assets` 静态、`/api/v1/*`、`/hx/*` 全走 handler，wails 只当壳。

## 实测对比（waydroid 同环境）

| 维度 | wails3 壳 | 手搓壳 | 谁好 |
|---|---|---|---|
| **部署体验** | 构建→装→渲染一把过（踩的坑全是第一次接触配置摩擦：阿里云 Gradle 镜像冲突、bindings、`application.Android` 是变量不是函数） | 踩了一整串真坑：SIGSYS（modernc lstat）→ 换 ncruces 驱动；ETXTBSY（重复打开覆盖写可执行文件）；主线程网络闪退（NetworkOnMainThreadException） | **wails3 明显顺** |
| **内存** | 228MB 单进程（WebView + .so 共享运行时） | App 267MB + hc-server 21MB = 288MB | **wails3 省 ~60MB**（单进程设计） |
| **体积** | APK 16MB（多一个 wails 运行时框架层 ≈ 8MB） | APK 5.7MB（服务端主体其实也是 16MB：ncruces 内嵌 wazero+sqlite.wasm） | 手搓壳小，爸妈手机无所谓 |
| **生命周期** | 框架管（进程/窗口/JNI 桥，无进程管理坑） | 自管 + 手打补丁（探测复用、tmp+rename、后台线程） | **wails3** |
| **系统集成** | 现成 API（StoragePath/通知/权限/键盘等 mobile_features 一整套） | 全手写 | **wails3** |
| **可维护性** | 壳层几乎零代码（main.go ~30 行），跟着上游走 | 壳层代码自己养，坑自己踩 | **wails3** |
| **黑盒程度** | 中（框架收编生命周期） | 全可控 | 手搓壳（符合"无黑盒"哲学，但成本在这） |

启动时间两者都在秒级，无本质差。

## 踩的坑（wails3 侧，都解决）

1. **你的 `~/.gradle/init.gradle.kts`（阿里云 Maven 镜像）与 Gradle 9 settings 策略冲突** → 用 `GRADLE_USER_HOME=/home/a1/.gradle-hc` 隔离，不动原配置
2. **wails3 CLI 无预编译二进制**，要源码编译 → 装 `libgtk-4-dev` + `libwebkitgtk-6.0-dev` 系统库
3. **`application.Android` 是变量不是函数**：`application.Android.StoragePath()` 不是 `Android()`
4. **module 名影响 bindings 生成**：homecast 无 wails JS 绑定（纯 HTTP），`src/main.ts` 里去掉 bindings 引用
5. 手搓壳侧包名实验的坑：manifest 改包名后 `android:name=".MainActivity"` 解析错位 → 用全限定类名 `com.homecast.app.MainActivity`（Java 类和构建脚本零改动）

## 结论

- **wails3 现在是实测更好的那个**：部署顺、内存省、生命周期框架管、系统集成现成。"beta"是官方标签（v3.0.0-beta.27，prerelease），不是"不可用"——真 API 变动风险存在，但迁移路径已验证（handler 挂载 + ensureHome 两招，随时能切回手搓壳兜底）
- **主线切 wails3**（本日决策）；手搓壳工程保留作兜底（已验证、无黑盒、随时可切）
- 体积差（5.7 vs 16MB）对爸妈手机不构成决策因素
