## 一、影响性能

### 1. 🔴 歌单 `Add` 持锁做网络请求

**位置**：`go/internal/service/playlist/playlist.go` L96-113

```go
func (p *PlaylistService) Add(bvid string) (*PlaylistItem, error) {
	p.mu.Lock()
	defer p.mu.Unlock()
	...
	info, err := p.client.GetVideoInfo(bvid)  // ← 持锁内网络 I/O（B站 API，30s timeout）
	...
	p.save()  // SQLite 写也在锁内
}
```

用户点"加到歌单"时，`p.mu` 被 **B站网络请求 + SQLite 写** 占住。期间 `Get()`/`Remove()`/`Clear()`（歌单列表渲染、删除、清空）全部阻塞。B站 API 慢或超时 → 整个歌单操作冻结。

**与第二批 `cast.controller` 同模式**（锁内网络 I/O），这是本项目反复出现的坏味道。

**修法**：先把 `GetVideoInfo` 放锁外（无锁取 info），再锁内 `append` + `save`。

### 2. 🟡 壳层每个 HTTP 请求都 open/write/close 日志文件

**位置**：`wails3/main.go` `logRequest` L57-72

```go
f, err := os.OpenFile(httpLog, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
if err == nil { f.WriteString(msg); f.Close() }  // ← 每请求一次文件系统调用
```

**每个请求**（含 SSE 心跳、progress 上报 4Hz、静态资源）都做一次 `OpenFile`+`WriteString`+`Close`。安卓 stderr 不可见所以落文件，但高频下这是**每请求 1 次 open/write/close 系统调用**，无任何缓冲/复用。

**修法**：包级 `*log.Logger`（内部有 mutex + 单文件句柄，`os.OpenFile` 一次），或带 channel 的异步写队列。

### 3. 🟡 `SpeakerSection` 页面渲染路径同步刷设备（网络）

**位置**：`hx/speaker.go:31-34`

```go
func (h *H) SpeakerSection(...) {
	...
	devices, err := h.Speaker.RefreshDevices()  // ← 渲染路径上同步调小米云
```

打开音箱面板（`/hx/speaker`，htmx 片段）每次都 `RefreshDevices()`（小米云网络）。网络慢则页面片段渲染卡住。且用户点"刷新"按钮也走同一函数——**前后不一**（自动加载与手动刷新同路径，都打小米云）。

**修法**：`SpeakerSection` 用内存 `ListDevices()`（无网络），仅在显式刷新时 `RefreshDevices()`。

### 4. 🟢 `CastStatus` 每次 UPnP 网络

**位置**：`hx/cast.go:49`（`Cast.Status` → `GetTransportInfo`+`GetPositionInfo`+`GetVolume`）

若前端轮询此端点（`cast-ui.js`），每次 UPnP 三连调。当前未轮询（SSE 驱动），低危；但保留为"若加轮询会放大"的提示。

**修法**：无 UPnP 轮询；若加，走 SSE 或本地缓存。

## 二、低能

### 1. 🟢 `30280` 硬编码 6 处，有常量不用

**位置**：
- `go/hx/speaker.go:92`
- `go/server/server.go:150`
- `go/internal/service/speaker/speaker.go:445`（`playNextAuto`）
- `go/internal/service/playback/playback.go:336`（Next）
- `go/internal/service/playback/playback.go:383`（Prev）
- `go/internal/api/speaker.go:194`

**`bilibili.Audio192K = 30280` 已定义**（`bilibili/audio.go:12`），但上述 6 处硬编码字面量。改音质档位/加注释时漏改一处就前后不一致。

**修法**：全部改 `bilibili.Audio192K`。（第一批只在 playback/server 提过 4 处，本批补全到 6 处。）

### 2. 🟢 `SpeakerPlay` 日志带整个 `res`

**位置**：`hx/speaker.go:95`

```go
log.Printf("[speaker play] bvid=%s did=%s err=%v res=%v", bvid, did, err, res)
```

`res` 是 `map[string]any`（含整个播放响应），每次播放打一整条可能很大。且这是**每次播放**都打，含敏感/冗余数据。

**修法**：只打 `res["code"]`/`err`，不打全量 map。
