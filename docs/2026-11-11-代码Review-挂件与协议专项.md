## 一、低能

### 1. 🔴 挂件 `time.AfterFunc` 回调里调 Xlib，无 `XInitThreads`

**位置**：`wails3/widget/display_linux.go:136-137` + `cglue.c:215`

```go
time.AfterFunc(800*time.Millisecond, func() { C.hc_keep_above() })   // ← Go timer goroutine 调 Xlib
time.AfterFunc(2000*time.Millisecond, func() { C.hc_keep_above() })
```

`hc_keep_above`（`cglue.c:215`）用 `XInternAtom`/`XChangeProperty`/`XSendEvent`/`XFlush`——**纯 Xlib**。这两个回调在 **Go 的 timer goroutine** 里执行，不是 GTK 主线程。而 `grep XInitThreads` 全项目**无结果**——Xlib 未做线程初始化。

- 若 `_dpy()`（`XOpenDisplay`）首次被这两个 timer goroutine 触发 → **Xlib 跨线程初始化**；
- 即使 `_dpy` 已在主线程初始化，跨线程 `XSendEvent`/`XFlush` 在无 `XInitThreads` 下也是**竞态/未定义行为**。

**修法**：要么在 C 侧 `main`/`gtk_init` 前 `XInitThreads()`；要么把 `hc_keep_above` 调度回 GTK 主线程（`gdk_thread_add_idle` / `gtk_glib_idle_add`）；要么删掉这两个 `AfterFunc`（800ms/2000ms 的重复置顶，用 `gdk` 的 map-event 即可）。

### 2. 🔴 `display_linux.go` 的 `C.CString` 无 `C.free`（C 内存泄漏）

**位置**：`display_linux.go:93,102,104,120,122`

```go
C.gtk_widget_set_name(ctrl, C.CString("hc-ctrl"))         // ← 无 C.free
C.gtk_button_new_with_label(C.CString(b.Label))           // ← 无 C.free
C.gtk_widget_set_name(bb, C.CString("hc-btn"))            // ← 无 C.free
C.gtk_button_new_with_label(C.CString("🔒"))              // ← 无 C.free
C.gtk_widget_set_name(lockBtn, C.CString("hc-lock"))      // ← 无 C.free
```

cgo 规则：`C.CString` 分配 C 堆内存，Go GC 不管，**必须 `C.free`**。对照 `display_darwin.go:205-214` 用了 `defer C.free`——**linux 版漏了，前后不一**。GTK 会复制 label/name（`g_strdup`），所以这里纯泄漏。

- 启动一次性（`Init` 一次），泄漏量小；
- 但若 `Init` 被重试/重建（如挂件重启），**每次泄漏 5+ 份 CString**。

**修法**：给每个 `C.CString` 加 `defer C.free(unsafe.Pointer(...))`，或提前 `var s = C.CString(...); defer C.free(...)`。

### 3. 🟡 `widget.go` `Start` 里 `newDisplay()` 创建两次

**位置**：`wails3/widget/widget.go` `Start`

```go
x, y := loadPos()
d := newDisplay()              // ← 第一个实例：只用来 ScreenSize
sw, sh := d.ScreenSize()       //    Init 前调用，注释自己都说"Init 后 ScreenSize 才可靠"
...
disp = newDisplay()            // ← 第二个实例：真正用
if err := disp.Init(x, y); err != nil { ... }
```

`d` 创建后**从未 Init、从未使用**（除了那次不可靠的 `ScreenSize`），随即被 `disp` 覆盖。后面 `disp.Init` 后再 `disp.ScreenSize()` 取准值（L"校准"注释）。第一个 `d` 纯冗余。

**修法**：删第一个 `d`/`ScreenSize`，直接用 `disp := newDisplay()`，Init 后取 ScreenSize。

### 4. 🟢 `widget.go` `postOffset` 字符串拼 JSON

**位置**：`widget.go:postOffset`

```go
body := strings.NewReader(`{"bvid":"` + bvid + `","offset":` + fmt.Sprintf("%.1f", cur) + `}`)
```

手拼 JSON（bvid 是 `BVxxx` 无特殊字符所以安全，但仍是低能）。应 `json.Marshal(map[string]any{...})`。

### 5. 🟢 `api/lyric.go` `Select`/`Offset` 的 body 兼容 hack 混乱

**位置**：`api/lyric.go:Select`（L"body.BVID 为空才 decode body"）、`Offset`

```go
body.BVID = strings.TrimSpace(r.FormValue("bvid"))  // query/form 优先
...
if body.BVID == "" { json.NewDecoder(r.Body).Decode(&body) }  // 才读 JSON body
```

`r.FormValue` 对 `application/json` 请求会尝试解析（ParseForm 不消费 JSON body，返回空），于是 fallback 到 JSON decode——但此时 **`r.Body` 已被 `FormValue` 的 `ParseMultipartForm`/`ParseForm` 部分消费/peek 过**（取决于 Content-Type），`json.Decode` 可能读到空。注释"query 优先，防安卓壳丢 body"的意图是对的，但实现边界不清（query 有 bvid 就完全跳过 body，body 里独有字段如 name/artist/duration 会丢）。

**修法**：明确二选一——`Content-Type == application/json` 就走 JSON decode，否则走 form；不要混用。

## 二、前后不一

### 1. 🟡 `GetBestVideoURL` 复用"音频取流"函数拿视频流

**位置**：`bilibili/audio.go` L"GetBestVideoURL"

```go
func (c *Client) GetBestVideoURL(bvid string, cid int) (*DashVideoItem, error) {
	stream, err := c.GetAudioStream(bvid, cid, AudioFLAC)   // ← 函数名叫 GetAudioStream，qn 用 AudioFLAC(30250)
```

函数名叫"Audio"，却拿来取**视频**流；`AudioFLAC` 是**音频** qn，传给视频流请求语义错位。目前能跑是因为 `fnval=16` 让 B站返回完整 DASH（含 video+audio），但**命名/语义与实现脱节**，且 `AudioFLAC` 作视频 qn 是错用。

**修法**：单独实现 `GetDash`（fnval=16 取完整 DASH），音频/视频分别从 `Dash.Audio`/`Dash.Video` 取；`GetBestVideoURL` 不再调 `GetAudioStream`。
