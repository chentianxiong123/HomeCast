## 背景：现在的绕法（不优雅，要改掉）

当前架构把 Go 后端 handler 塞进 wails 的 `Assets.Handler`（静态资源通道），导致一连串 hack：

```
WebView ──► wails Assets.Handler(Go后端handler)  ← 模拟静态资源，其实是后端
              ↓
             injectHcEnv                         ← 往 HTML 里注脚本标记环境
              ↓
        ┌──► 你的 handler ◄─────────────────────┐
        │ (wails 内部端口)                      │
        │                                       │ listenBackend 0.0.0.0:28976
        │                                       │ (同一 handler 挂第二遍)
      挂件 ◄─────────────────────────────── 音箱/DLNA/局域网
```

5 个 hack 全是这个模型的并发症：

| # | hack | 原因 |
|---|---|---|
| 1 | `Assets.Handler = 后端 handler` | wails 静态通道被塞进完整后端 |
| 2 | 双端口并行（wails 内部 + 0.0.0.0:28976） | 同一 handler 挂两遍 |
| 3 | `injectHcEnv` 往 HTML 末尾注 `<script>window.hcEnv='desktop'` | WebView 内 JS 无法自知环境 |
| 4 | 安卓 `?hc=1` query 代替 `HX-Request` header | wails asset 桥丢 header/body |
| 5 | `CORS *` 全放开 | wails:// origin 跨域（本不该有） |

另有：`frontend/dist`（wails 默认模板）嵌进二进制但从未被请求。

## 查证结论（wails3 v3.0.0-beta.25 源码）

读 `~/go/pkg/mod/github.com/wailsapp/wails/v3@v3.0.0-beta.25/`：

1. **安卓"三丢"是物理限制，fork 也修不了**
   - `internal/commands/build_assets/android/.../WailsPathHandler.java`：
     `handle(String path)` 接口只给 path，`serveAsset(path, "GET", "{}")` 写死 GET+空 body
   - `shouldInterceptRequest` 也拿不到 body —— Android WebView API 天花板
   - wails 自己都受害者（`/wails/` 前缀手动拼回 query）

2. **wails WebView 支持加载绝对外部 URL**
   - `internal/assetserver/assetserver.go:149 GetStartURL`：`baseURL.Parse(userURL)`
   - 绝对 URL（带 scheme）直接返回自身 → WebView 可 `loadUrl("http://127.0.0.1:28976")`
   - 与手搓壳（explore/android/MainActivity.java）同模型

3. **wails 桌面系统 API 现状（beta.25）**
   - ✅ 内置：单实例锁、系统托盘、剪贴板、文件对话框、全局快捷键、多窗口/生命周期
   - ❌ 桌面系统通知：无 Notification API（仅 iOS 有）
   - ❌ 桌面深链：无公开 API（仅 Darwin 内部 handler）
   - 缺的两项用 WebView 内 HTML5 Notification / 第三方库替代（见步骤 8）

## 目标架构（优雅方案）

```
hcexp (wails 壳)                                ── 只做系统壳
  ├── Go 后端 http.ListenAndServe("0.0.0.0:28976")   ── 一个服务一个端口
  ├── WebView ──► http://127.0.0.1:28976              ── 真实 HTTP 同源
  ├── 挂件 / 音箱 / DLNA ──► 同一端口                 ── 全走同一个
  └── wails 系统 API（托盘/单实例/剪贴板/对话框/快捷键）
```

与手搓壳同模型，但白拿 wails 生命周期+系统 API+打包链路。

## 已知坑备忘

- **安卓明文 HTTP**：必须 networkSecurityConfig 放行 127.0.0.1，否则 WebView 白屏
- **安卓包名锁死** `com.wails.app`：不动
- **桌面系统通知/深链**：wails beta.25 无 → WebView Notification API 或第三方库兜底
- **WebView 直连后 wails 事件桥**（desktopEventsBridge）：挂件若仍要推事件到界面，走 HTTP 轮询即可，事件桥可退役
- **端口占用**：28976 被占时启动失败，桌面 shell 检测到要提示（原 listenBackend 静默失败，迁移后需显式处理）
